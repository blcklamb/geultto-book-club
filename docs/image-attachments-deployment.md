# 이미지 첨부 배포 및 PR #18 리뷰 반영

PR #18의 리뷰 6건은 모두 현재 코드에서 재현 가능한 문제로 판단하여 반영했습니다.

| 리뷰 | 확인 및 수정 |
| --- | --- |
| 4~5MB 전송 방식 불일치 | 클라이언트의 이전 전송 경로가 남아 있었습니다. 모든 파일은 비공개 임시 Storage로 전송하고, 서버가 다운로드하여 실제 크기·파일 헤더를 검사한 뒤 공개 버킷에 저장합니다. |
| Storage 직접 업로드 우회 | 인증된 회원에게 공개 버킷 INSERT 권한이 있었습니다. 두 이미지 버킷의 직접 쓰기를 차단하고 서버 전용 클라이언트로만 처리합니다. |
| 업로드 중 취소 시 파일 잔류 | 응답을 받기 전에는 경로가 없었습니다. 먼저 생성한 업로드 ID로 취소 상태를 DB에 기록하며, 취소가 준비 요청보다 먼저 도착해도 이후 업로드를 차단합니다. |
| 알림 발신자 위조 | 하이라이트 댓글·답글·반응의 쓰기 정책이 작성자를 제한하지 않았습니다. 모든 알림 원본 테이블의 INSERT·UPDATE·DELETE를 활성 회원 본인의 활동으로 제한합니다. |
| Realtime 반응 표시 미갱신 | 반응 목록이 최초 props만 복사했습니다. 새 서버 목록을 받으면 내부 상태를 동기화합니다. |
| 동일 이미지 반복 삽입으로 개수 우회 | 경로 중복 제거 이후 개수를 검사했습니다. 본문 이미지 노드의 출현 횟수를 검사하며, 에디터에서도 3개 초과 시 저장을 막습니다. |

## 배포 순서

1. 기존 `202609070100`~`202609070102`에 이어 `supabase/migrations/202609070103_review_security_fixes.sql`을 적용해주세요. 새 마이그레이션으로 기존 정책을 교체합니다.
2. 해당 Vercel 배포 환경에 다음 서버 전용 환경 변수를 설정해주세요.
   - `SUPABASE_SERVICE_ROLE_KEY`: 해당 Supabase 프로젝트의 service-role 키입니다. `NEXT_PUBLIC_` 접두사를 붙이지 마세요.
   - `CRON_SECRET`: 임시 파일 정리 API를 보호할 충분히 긴 무작위 비밀 값입니다.
3. 애플리케이션을 배포해주세요. `vercel.json`의 정리 작업은 매일 00:00 UTC에 `/api/images/cleanup`을 호출합니다. 별도 호스팅에서는 같은 API에 `Authorization: Bearer <CRON_SECRET>` 헤더를 보내는 일일 스케줄을 설정해주세요.

개발 및 Preview에서도 환경 변수와 마이그레이션이 필요합니다. [Vercel 정리 작업 설정](https://vercel.com/docs/cron-jobs/manage-cron-jobs)에 따라 정기 실행은 프로덕션 배포에서 동작하므로 Preview의 정리는 필요할 때 인증된 API 호출로 실행해주세요.

## 취소 및 정리 동작

취소 요청은 업로드 ID를 취소 상태로 바꾸고 두 버킷의 파일 제거를 시도합니다. 공개 저장과 취소가 겹치면 상태 갱신 결과를 확인하여 공개된 파일도 제거합니다. 제거 실패 시 화면에서 재시도할 수 있습니다.

네트워크 중단, 브라우저 종료, 서명된 업로드가 늦게 끝나는 경우를 대비해 DB 기록을 유지합니다. 정리 작업은 생성 후 24시간이 지난 기록을 한 번에 최대 1,000건 처리합니다. 정기 실행 주기를 포함하면 보통 24~48시간 이내에 미사용 파일이 정리되며, 처리량을 넘는 경우 다음 실행에서 이어집니다. 저장된 본문·댓글에서 참조하는 공개 이미지는 유지합니다. 정리 중 Storage 오류가 발생하면 기록을 남겨 다음 실행에서 재시도합니다.
